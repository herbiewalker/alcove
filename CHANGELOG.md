## [Unreleased]

## [0.1.3] - 2026-11-18

Upgrading from 0.1.2: the update restarts the container and migrates the database (schema 10 to 11, two new tables for two-step sign-in) by itself; your data and key are untouched and there is nothing else to do. Everything below is optional or automatic: two-step sign-in is off until an administrator turns it on, and the default time zone setting only takes over from `ALCOVE_TZ` once you save one. Not yet tried by hand: two-step sign-in with a real authenticator app, the QR codes with a real phone camera, and thumbnails on real phone photos. Going back to 0.1.2 means restoring the instance backup taken before the update (RUNBOOK section 13).

### Added
- Two-step sign-in for administrators (D-49): Account, Two-step sign-in sets it up with a QR code for any authenticator app, and only turns it on after you type a correct code from the app. You then get ten one-time recovery codes. Signing in then needs your password and a 6-digit code (or a recovery code); five wrong codes lock that step for ten minutes. New recovery codes and turning it off need a current code. Other devices are signed out when it changes. If the phone is lost: a recovery code, another administrator's reset on People, or `alcove reset-2fa` on the server. Health shows how many administrators use it, warns when recovery codes run low, and shows the server clock. Schema 10 to 11 (additive) migrates by itself on the next start.
- Hide screen (D-48): a Hide button in the top bar covers the page with a blank grey sheet and a neutral tab title; tap it or press Escape to come back. It only covers: you stay signed in and nothing is stored or sent. It needs the page script and stays hidden without it.
- QR codes (D-48): Admin shows the server address with a QR code, and a page that shows a new invite or space code adds a QR code for the join page, so a phone can open it by camera. Drawn by Alcove itself, no outside service. The secret code is never in the picture.
- Health page (D-47): Admin, Health shows what the server holds and what needs attention at a glance: no backup folder, never backed up, a backup older than 30 days, no restore drill yet, the admin log never or not recently checked or failing its check, a network change waiting to be confirmed. The console home shows how many things need attention. Counts and states only; opening it is logged.
- Admin search (D-46): Admin, Search everything finds words in every person's current notes and in their partners' names and notes, whatever they share. Each search is logged by length and result count only, never the words, and opening a result is logged like any look at someone's data. Entries a person deleted are not searched.
- Admin log filters and export (D-45): filter the log by who, action (or the start of one), target type and date range, keep the filter while paging, and download the matching lines as a CSV. The download needs your password again, holds only ids and field names, is safe to open in a spreadsheet, and is itself written to the log.
- Thumbnails (D-44): the photo galleries load small pictures made on demand (360 pixels on the long side) instead of every full picture, so they open much faster on a phone. They are kept only in memory for ten minutes, never written to disk, carry no metadata, sit behind the same gates as the picture, and a picture that cannot be shrunk is sent whole. No migration, nothing to do when updating.
- Default time zone setting: Admin, Network and security now has a "Default time zone" card (needs your password again, logged by field name). The saved zone beats `ALCOVE_TZ`, so a rebuilt or force-updated container whose variables were reset cannot change what people see. Empty goes back to `ALCOVE_TZ`. Stored data is never touched.

### Fixed
- A photo shared in a space (and its thumbnail) keeps its rotation. Cleaning removed the whole EXIF block, including the Orientation tag, so phone portraits showed on their side to other members. The tag is now kept alone in a block that holds nothing else.

### Changed
- Wording: Alcove is described as being for couples (partners who share their Tryst data), not for families, in the README, the Unraid template, the Spaces page and the requirements. The README's warning box is gone; the same trust statement stays under Known limitations and in the threat model.
- Documentation brought up to date with what is built: the README (status, install, what is and is not proven), RUNBOOK sections 13 to 15 (updating and going back, editing and exporting to the phone, editing as the administrator), the requirements status table, the architecture components and flows, the data model, threat model risks R28 to R30, setup notes for the emulator check, and the critical assets list.
- RUNBOOK: going back to an older release means restoring the instance backup taken before the update. An older build refuses a database that a newer one has migrated, so setting the image tag back does not work.

## [0.1.2] - 2026-11-15

Upgrading from 0.1.1: the update restarts the container and migrates the database (schema 9 to 10, one new table) by itself; your data and key are untouched and there is nothing else to do. Before your first real export, read the page it opens: export a fresh backup on the phone first, and restore with "Replace my current data with the backup" on.

### Added
- Export to Tryst (D-43): My data, Export to Tryst writes your current data, with every edit, addition and deletion, as a new Tryst backup. It shows what changed since your upload, asks you to confirm you exported a fresh backup from your phone first, asks for your password again, and downloads `alcove-<name>-<date>.tryst`. A deleted entry's photos are left out. The file is read back and checked before it is offered. Proven on Tryst 0.6.5 on an emulator with "Replace my current data with the backup" on; never switch that off. Not yet tried on a real phone.
- Admin editing (D-42 slice 4): the administrator can open, edit, delete and restore any person's entries and rename their partners (People, Data). Every look and every change is written to the admin log with the table, the row and the field names, never the values; changes ask for the password again; the administrator restores a deleted entry for 45 days.
- Editing (D-42): add, delete and restore entries; edit your own entries (time, length, rating, mood, who started it, protection, orgasms, acts, positions, kinks, settings, toys, occasions, note) and rename your partners from My entries. Each save is a new version with a history and an undo; your uploaded backup is never changed, a rebuild keeps your edits, spaces see them at once. Store schema v10.
- Photo galleries (D-40): My photos under My data, and Photos on each space page. Blurred until tapped, lazy loaded, 24 to a page, through the same gates as shared entries.

### Changed
- Entry times use the Tryst style ("Jan 2, 2026, 3:04 PM"); a birth date from a backup is read in the person's own zone; the profile page can fill the time zone from the device (D-41).


## [0.1.1] - 2026-11-14

Upgrading from 0.1.0: the update restarts the container and migrates the database (schema 6 to 9) by itself; your data and key are untouched. Afterwards, open Admin, Backups and press **Rebuild now** once, so photos from the upload you already have are copied out and appear on your entries.

### Changed
- The Unraid template and `.env.example` default the time zone to `America/New_York`. The running container keeps its own setting; change it in the Docker tab.
- The runbook's key-copy drill command needs `--tmpfs /tmp` (and `--user 0:0` for a root-only copy on the flash drive), and the scripts are marked executable.
- The `no-outbound` guard now matches calls (`http.Head(`) instead of any use of the `http.Header` type.

### Added
- Photos (D-39, M7, F19): the photos of your current upload are copied out of it, encrypted under your data key, so they open instantly; they show on the entry page blurred until tapped, for you and, through the space, for members; a member sees them only where the entry is shown and its owner includes photos, and a caption follows the note choice. A photo's place is hidden unless its owner turns on a new "Show where my photos were taken" choice; the picture file itself is cleaned of EXIF, XMP, comments and thumbnails before anyone else gets it (JPEG and PNG; other formats are never shared), so the place cannot leak through the file. Schema v9.
- Search (D-38): a Search page with two scopes, your own entries (notes, and your partners' names) and the notes a space shows you. It goes through the same gate as every other shared view, honours each owner's choice to keep notes out, never searches partner names in a space, and is a POST so what you look for stays out of addresses, history and logs. Words are quoted for the engine so nothing typed can act as an operator. Results link to the entry page, newest first.
- Open an entry (D-37): tapping a date in My entries, in a space's shared list or in the calendar's day view opens the whole entry, read-only: length, rating, mood, who started it, protection, orgasm count, acts, positions, kinks, settings, occasions, toys, finish locations, partners and the note, with catalog items shown by name. Through a space it goes through the same gate as the list, honours the owner's choices (no note if they keep notes out, partners not named unless allowed) and returns the same "not found" page for anything hidden. Photos are not shown yet.
- Progress and status for every wait (D-36): a "Working..." bar with a running clock for any form that takes a moment (sign-in, creating or deleting a person, deleting and restoring an upload, starting a backup, a check or a drill, and so on), buttons disabled so a second click cannot repeat the action; the upload bar now carries on as an animated "Checking the backup" bar with a clock; "Download all my data" says it is preparing the file until the browser has really received it; a running backup, check or restore drill shows an animated bar and how long it has run. The one script is now `ui.js` and loads on every page; nothing works differently without it.

## [0.1.0] - 2026-11-14

First release. Everything below is new in it.

### Added
- L1 deploy kit: an Unraid template (`deploy/unraid-template.xml`, following `:stable`, least-privilege flags, key mounted read-only, one LAN port), a guard (`unraid-template`) that fails CI if the template ever loosens the container, and RUNBOOK sections for the first live deploy (with the validation ladder and a real-phone check) and for putting HTTPS in front (Caddy, Nginx Proxy Manager, `tailscale serve`, each with a check that Alcove still sees the real client address).
- M4 piece D, compare metrics and time zones (D-35, F13): `internal/compare`, a versioned metrics registry (At a glance, Rhythm, Trend, Variety) built only from what `share` lets through, with per-period choices and a member whose backup is from a newer Tryst named and left out rather than shown wrongly; a Compare page per space; a per-member time zone on the profile page (`ALCOVE_TZ` sets the server default, UTC if empty) that decides each person's day boundaries everywhere; the zone database is built into the binary. Schema v8. This completes M4.
- M4 piece C, the shared calendar (D-34, F12): a month grid per space with a lettered, coloured marker per member per day, a highlight when two or more members were active, and a day view listing that day's entries; no script, plain links; `share.Days` shares one gate definition with `share.Entries` and a test keeps them in step across every way of hiding an entry. Days are UTC for now.
- M4 piece B, profiles and member cards (D-33, F26, F28): a profile page (name shown to others plus nine optional fields, each with its own share tick, everything private to start); "fill from my latest backup" lists what the backup's profile holds and imports only what is ticked, never turning sharing on; the birth date is stored for the owner, must be an adult's, and is shown to others as an age only; member cards on the space page come from `share.Cards`, which applies the same membership, pause and consent rules as entries. Schema v7; purge removes profiles. No profile photo yet.
- M4 piece A, the shared-entries gate (D-32, F11): `internal/share.Entries`, the one read gate for other people's entries (viewer must be an active member; members whose account is disabled or deleted, who are paused, who left or were removed, who asked but were not admitted, or who agreed to older wording are never shown; an entry its owner marked private never passes; the include-notes choice removes the note); a "My entries" page with a per-entry private toggle; a space's shared-entries list; and a re-agree screen. The join wording is now accurate and `ConsentVersion` is 2. Schema v6 (`entry_flag`); purge removes a person's flags. Mutation checks prove each condition in the gate is load-bearing.
- M3 piece D, spaces and invites (D-31, F4 to F6, F27): any signed-in person can start a space; `internal/spaces` and its single visibility gate; one-time space invites, a revocable space code that only lets a person ask, and admin server invites, all hashed at rest and redeemed in one transaction that spends the code and creates the account; a join screen that states exactly what is shared and records the agreed version; leave, remove, hand over, soft delete and restore; the admin's Spaces page (logged); purge removes deleted spaces and a purged account's memberships, handing on ownership. Schema v5. Constraint 11 is now covered by tests that throw every kind of bad code at the only unauthenticated account-creating route.
- M3 piece C, accounts and retention (D-30, F2, F3, F16, F21, N13): the admin People page (add a person with a temporary password shown once and forced to change at first sign-in; disable, enable, reset, delete with a grace period, restore; nobody can lock out the last administrator), a person's own delete, restore and "download all my data" (step-up is now available to everyone), the admin's Recently deleted page, `internal/retention` (the 10 and 45 day windows, both configurable; an hourly and on-demand purge that really deletes files, rows, search index, remembered password and data key; a sweep that finishes what a crash left), `alcove reset-password` for a lost admin password, and a lock on the data directory so a second process is refused instead of corrupting the store. Schema v4. The end-to-end smoke now covers all of it on the real image.
- M3 piece B, upload and revisions (D-29, F7 to F10, F30): the My data page and a streamed upload route (CSRF token checked before the file, a longer read deadline for that one route, a fast 413), `internal/ingest` (the file is stored verbatim, then judged, then recorded in one transaction with its revision, row cache, search index and sealed password; any refusal records nothing), duplicate refusal by SHA-256, a newer Tryst schema kept read-only, a rebuild of the cache and search from the stored upload (admin button, logged), a progress bar (the one same-origin script; the CSP gains `script-src` and `connect-src` for `'self'` only), `alcove test-backup` for synthetic backups, and an upload, refusals and rebuild flow in the end-to-end smoke. Schema v3.
- M3 piece A, instance backup and restore drill (D-28, F23): one archive of ciphertext per backup with a hashed index and a checksum file, taken consistently while the server runs and never overwriting; an admin Backups page with background jobs for back up, verify and restore drill, and retention; `alcove backup-verify`, `restore` and `drill` for use with no server, including proving a key copy by restoring a real backup with it; `RUNBOOK.md`. The plaintext guard now also covers backups, and the whole flow is smoke-tested end to end on the real image in CI and the live smoke.
- M2b accounts, admin log and UI shell: first-run setup with a one-time code from the server log, Argon2id sign-in, sessions with step-up, a hash-chained admin log with a viewer and a verify button, the mobile-first light/dark/auto UI with the Alcove mark, strict CSP and CSRF, the network gate (allowed networks, proxy mode, require-TLS, a 60-second self-reverting change) and its environment overrides, and the web unlock page for a passphrase-wrapped key (D-27, schema v2). Smoke checks in CI and `scripts/smoke-live.sh` cover first run, the headers and the gate on the real image.
- M2a storage foundation: the master key file (`alcove keygen`, `alcove keycheck`, optional passphrase-wrapped form), the sealed in-memory database with full-text search and per-user data keys (`internal/store`, `internal/seal`), the blob store, startup that refuses to run with the key inside the data directory, a missing or wrong key, or a scratch directory that is not tmpfs, and the armed `no-plaintext` guard. Smoke checks in CI and `scripts/smoke-live.sh` cover the real image.
- S1 round-trip spike (emulator, Tryst 0.6.5, schema v19): wipe-first restore is exact, merge restore deletes partner links, ZIP entries must be DEFLATED. Findings in the D-15 addendum; synthetic generator now writes DEFLATED media entries (regression test).
- The Alcove logo: `docs/img/alcove-icon-512.png` (master tile), `docs/img/alcove-banner.png` (README banner), `deploy/icon.png` (512 px, for Unraid). The header mark and favicons were regenerated from the new tile.
- M1 Tryst reader: `internal/trystbk` (header, bounded decrypt, Zip-Slip and zip-bomb checks, lossless generic table reader, `Seal` writer, `SchemaStatus`) and the synthetic backup generator `internal/trystbk/synth`. Adapted from Sanctum's reader (MIT notice kept in `internal/trystbk/NOTICE`). First third-party dependencies: tink-go and x/crypto.
- A guard that fails when a file that `.gitignore` excludes is tracked (it caught a build artifact force-added by mistake in the kickoff commit; the file is untracked now but remains in that commit's history).
- M0 container and CI: Dockerfile (distroless, non-root, digest-pinned), compose file, `.env.example`, CI and release workflows, release and live smoke scripts, and a dependency and licence gate (`scripts/dependencies.allow`).
- Project kickoff: AGPL-3.0 license, hard constraints and size class in `CLAUDE.md`, scaffold server with
  `/healthz`, bootstrap script, Makefile and constraint guards, and the seeded design documents
  (requirements, architecture, threat model, data model, roadmap, decision log).
